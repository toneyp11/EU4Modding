# This file used to hold `atools.1`, a hidden province_event that re-scheduled
# ITSELF every 30 days to act as the mod's global timer. That pattern corrupts
# the save: an event fired from inside another event stores its firing context,
# so every tick nested inside the previous one and the chain never unwound. It
# was serialised into the save on the hub province and grew one level per month.
#
# Measured in a real 1444 game at 1590: province 1 had reached 5,007,426 bytes
# (median province: 4,042) containing 1,840 nested 'from' scope blocks, 511 tabs
# deep. At roughly 2 stack frames per level that is ~3,680 frames - and the game
# died with EXCEPTION_STACK_OVERFLOW at a measured 3,701-3,703 frames, every
# ~146 game years, whatever the tools themselves were doing. Vanilla could load
# the same save fine only because it has no `atools.1` defined and threw the
# pending chain away.
#
# The tick now lives in `on_monthly_pulse` (common/on_actions/atools_on_actions.txt),
# which the engine fires with a FRESH scope each month - nothing accumulates.
#
# If you ever need a delayed event here, do NOT let it re-schedule itself.
